MULTI-TENANT DIGITAL MENU & QR ORDERING PLATFORM - DEPLOYMENT GUIDE
==================================================================

This guide explains how to deploy the Database, Backend (Express/Prisma), and Frontend (Vite) of this project to production environments.

------------------------------------------------------------------
PART 1: DATABASE DEPLOYMENT (Neon or Supabase)
------------------------------------------------------------------

You will need a hosted PostgreSQL database. Neon or Supabase are the recommended options.

A. Using Neon (Preferred for Serverless PostgreSQL)
1. Sign up/Log in to https://neon.tech and create a new project.
2. Under "Connection Details" on your Dashboard:
   - Select "Prisma" or "PostgreSQL" from the connection string dropdown.
   - Copy the Pooled connection string (used for application queries).
   - Copy the Direct connection string (used for Prisma migrations).
3. Keep these connection strings ready for the backend environment setup.

B. Using Supabase
1. Sign up/Log in to https://supabase.com and create a new project.
2. Go to Project Settings > Database.
3. Scroll down to the Connection Pooling section:
   - Copy the Connection String for Transaction Mode (port 6543, standard for `DATABASE_URL`).
   - Copy the Connection String for Session Mode (port 5432, standard for `DIRECT_URL`).
4. Keep these connection strings ready for the backend environment setup.

------------------------------------------------------------------
PART 2: BACKEND DEPLOYMENT (Render, Railway, or VPS)
------------------------------------------------------------------

The backend is built with Node.js, Express, and TypeScript. You can deploy it to platforms like Railway, Render, Heroku, or a VPS.

A. Configure Production Environment Variables (.env)
On your hosting platform, set the following environment variables:

  PORT=5000
  DATABASE_URL="<your-hosted-pooled-connection-string>"
  DIRECT_URL="<your-hosted-direct-connection-string>"
  JWT_SECRET="<generate-a-strong-random-secret-key>"
  FRONTEND_URL="<url-of-your-deployed-frontend>"
  
  # Cloudinary Credentials (for menu item images and logos)
  CLOUDINARY_CLOUD_NAME="<your-cloudinary-cloud-name>"
  CLOUDINARY_API_KEY="<your-cloudinary-api-key>"
  CLOUDINARY_API_SECRET="<your-cloudinary-api-secret>"

B. Build & Start Commands
Configure your deployment service with these shell commands:

  # 1. Install dependencies
  npm install
  
  # 2. Build the TypeScript code
  npm run build
  
  # 3. Apply database migrations to the hosted database
  npx prisma migrate deploy
  
  # 4. (Optional) Seed the database with initial menus/categories
  # Note: Run this once during setup
  npm run db:seed
  
  # 5. Start the production server
  npm start

------------------------------------------------------------------
PART 3: FRONTEND DEPLOYMENT (Vercel, Netlify, or Static Hosting)
------------------------------------------------------------------

The frontend is a static React application built using Vite. It can be hosted for free on platforms like Vercel or Netlify.

A. Configure Build Environment Variables
During the frontend build configuration, define the environment variable pointing to your hosted backend:

  VITE_API_URL="<url-of-your-deployed-backend>"  (e.g., https://your-backend.railway.app)

B. Build Settings
Provide the following settings to the hosting provider:

  - Build Command: npm run build
  - Output Directory: dist (or build)
  - Install Command: npm install

C. Router Redirects (Crucial for Single Page Apps)
Vite uses client-side routing. To avoid 404 errors when visitors refresh a page (like `/menu/cafe-central`), add a routing redirect rule:

  - For Vercel (vercel.json in the frontend root):
    {
      "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
    }
  - For Netlify (_redirects file in the dist/ folder or public/ folder):
    /*   /index.html   200

------------------------------------------------------------------
PART 4: VERIFICATION
------------------------------------------------------------------

1. Visit your backend health endpoint: `https://your-backend.com/health`
   It should return:
   {"status":"ok","database":"connected"}
   
2. Open your frontend website. Sign up a new restaurant and check if the logo upload and menu image uploads successfully save to Cloudinary and display correctly.
